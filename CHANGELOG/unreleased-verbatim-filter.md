- A `verbatim` filter escapes the style-tag brackets in its input, so a command that prints a generated file, a JSON Schema, a regex or a TOML snippet through a template writes `{{ body | verbatim }}` and gets output byte-identical to what it handed the filter: a `[severity_map]` table header is text rather than a tag, and no longer fails the run under `STANDOUT_STRICT_STYLE_TAGS=1` or degrades to unstyled text plus a warning (for #551).
- **Breaking:** `style_as` escapes its value before wrapping it, so `{{ value | style_as('error') }}` renders a bracket in the value literally inside the style. It previously built `[error]...[/error]` from the raw value, so `missing [severity_map] table` opened a `[severity_map]` tag the caller never wrote — stripped with a warning, failed under strict style tags, or styled if the theme happened to define that name. A template that fed `style_as` text already carrying style tags now sees those tags rendered literally; write the style as tag syntax around the value instead (closes #551).
