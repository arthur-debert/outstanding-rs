- Refuse an application `help` that collides with standout's own, instead of panicking (issue #294). With `.help_handling(true)`, standout installs a `help` word wherever the install policy allows; an application that claimed the same name met clap's duplicate-subcommand debug assertion — `Command app: command name 'help' is duplicated` — a runtime panic on a configuration. Both spellings are now the typed `SetupError::DuplicateHelpWord`, each caught the moment it becomes visible: a command registered as `help` fails `build()`, while a `help` declared on the application's clap `Command` (by name or alias) is refused when that `Command` reaches a parse entry point, before anything is parsed. The message names the setting that installs the word and the two ways out — rename the command, or drop `.help_handling(true)`. The install policy is unchanged, and a CLI that never gets the word (help handling off, or flat-with-positionals without `.help_word(true)`) is unaffected, as is a `help` deeper in the tree.
- **Breaking:** `App::augment_command_with_help` returns `Result<Command, SetupError>`. It is the first point at which the application's clap `Command` is visible, so it is the only place a declared `help` can be refused; callers that augment by hand propagate the error rather than receiving a `Command` that panics when parsed.
