- Teach one idiom in all three reference clients (issue #416). `tdoo`, the minimal single-crate guide and the wizard's generated project now register the same way — one `#[derive(Subcommand, Dispatch)]` enum, `#[dispatch(pure)]` per variant, one `.commands(Commands::dispatch_config())` call — adapt the same way, name their version, answer a bare invocation with a default command, and resolve any value that has more than one source through `CommandConfig::input` and an `InputChain`. Reading the three side by side now shows one set of calls. The wizard's output changes most: it registered each command with `command_with` and `FnHandler`, took `#[matches] matches: &ArgMatches` and resolved every value by hand — `matches.get_one`, `std::fs::read_to_string`, an if-chain per source — named its template explicitly, and set no version and no default command. It now emits typed `#[handler]` parameters for values that come only from their own argument, an input chain for the rest, and lets the template convention resolve the command's template.
- Let the blessed registration carry an input chain: `#[dispatch(inputs = path)]` names a `fn(CommandConfig) -> CommandConfig` that declares the command's `CommandConfig::input` entries. Without it, a command whose value can arrive from an argument, a file or piped stdin had to be registered through the `command_with` escape hatch, which is what kept `tdoo` off the blessed registration path.
- Assert the wizard's output against the blessed idioms, not just against the compiler (issue #416). `generated_project_uses_the_blessed_idioms` checks one positive structural assertion per axis — the derive, the `#[handler]` parameters, clap-derive, `embed_templates!`, `embed_styles!` plus `default_theme`, and the input chain — before checking that no unblessed form (`command_with`, `FnHandler`, `#[matches]`, an explicit `template_name`, a `help_handling` call, a `Theme` constructor) survives. A negative-only grep passes on output that dropped the concern, so the positive half is the check and the negative half rides on top.
- The wizard no longer offers an optional input with a second source. `CommandConfig::input` resolves a value or fails, so an optional value that could come from a file or piped stdin had no spelling in the blessed input entry; the answer sheet now rejects the combination ("optional inputs only support argument source") the way it already rejects a repeated or path input with one. A command with no value at all is unchanged: an input that comes only from its own argument stays a typed `#[handler]` parameter, optional or not.
- A generated command run with none of its value's sources present now fails with the chain's message — ``input `document`: No input provided and no default available.`` — where the hand-written resolution said `document is required`. The value is missing at the same point either way; the wording is now the framework's rather than the generator's.
