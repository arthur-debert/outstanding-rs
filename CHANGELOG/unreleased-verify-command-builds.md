- `verify_command` no longer reports a handler that reads an argument a parent command declares `global(true)` as mismatched: it builds the clap `Command` first, the way the run path does, so a parent's globals are present on every subcommand it walks. A registration test over a correct application verifies clean, and one that called `Command::build()` itself before verifying can drop that call (closes #547).
- **Breaking:** building the `Command` first also changes two other verification reports. A questionnaire command now collides on a `--yes` or `--answers` that a parent declares `global(true)` — the collision standout's injected flags would hit at run time. And a `Command` that clap's own debug assertions reject, such as a positional argument carrying `ArgAction::SetTrue`, panics inside `build()` in a debug build instead of returning a `SetupError`; running that application produces the same panic (closes #547).
