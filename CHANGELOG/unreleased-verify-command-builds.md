- **Breaking:** in a debug build, `verify_command` on a clap `Command` that clap's own debug assertions reject — a positional argument declared `ArgAction::SetTrue`, say — now panics inside `build()` where it returned a `SetupError` before, because the handler-argument check builds a clone of the `Command`. It is the same panic running that application already produces (closes #547).
- `verify_command` no longer reports a handler that reads an argument a parent command declares `global(true)` as mismatched: it checks handler arguments against a built clone of the clap `Command`, and clap copies a parent's globals into a subcommand only during `build()`. Its other checks — reachability, questionnaire surfaces and the flag and command collisions — still read the `Command` as declared, the way the run path does. A registration test over a correct application verifies clean, and one that called `Command::build()` itself before verifying can drop that call (closes #547).
