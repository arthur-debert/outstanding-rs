- **Breaking:** in a debug build, `verify_command` on a clap `Command` that clap's own debug assertions reject — a positional argument declared `ArgAction::SetTrue`, say — now panics inside `build()` where it returned a `SetupError` before, because verification builds the `Command` first. It is the same panic running that application already produces (closes #547).
- **Breaking:** a questionnaire command now reports a `--yes` or `--answers` that a parent command declares `global(true)` as a conflict, because the built `Command` carries a parent's globals into every subcommand. That is the collision standout's own injected `--yes` and `--answers` would hit when the command runs, surfacing at verification rather than a new restriction (closes #547).
- `verify_command` no longer reports a handler that reads an argument a parent command declares `global(true)` as mismatched: it builds the clap `Command` first, the way the run path does, so a parent's globals are present on every subcommand it walks. A registration test over a correct application verifies clean, and one that called `Command::build()` itself before verifying can drop that call (closes #547).
