- **Breaking:** `RunError::new` refuses `RunErrorKind::Config` the way it already refuses `External` and `App`; construct a configuration failure with `RunError::config(message, error)`, which takes the cause and cannot drop it. Every configuration failure the framework raises now carries a `source()`: a clapfig resolution failure downcasts to `clapfig::ClapfigError`, so a caller can read the offending key and its file position instead of matching on rendered prose. Render and final-write failures gain the same shape through `RunError::render(message, error)` and `RunError::final_write(message, error, OutputKind)`. A render failure that had a cause now carries it — `standout::RenderError` from a template or serialization failure, `serde_json::Error` when a handler's own result would not serialize — and the final-write failures that #564 made inspectable keep their `std::io::Error`. `RunError::new` still accepts `Render` and `FinalWrite`, which have framework-composed failures with no underlying error (a command naming a template with no registry configured; an artifact with no destination selected) (closes #572).
