- `#[dispatch(pre_dispatch(first, second))]` names several hooks for one phase, and they run in written order; `post_dispatch` and `post_output` take the same list. The single-path spelling — `pre_dispatch = path` — is unchanged. A variant that repeated the key used to register the last one and drop the rest with no diagnostic; two hooks that were separate closures before the derive had to be collapsed into one function calling both. Repeating the key now fails expansion and names the key, whether the two occurrences sit in one `#[dispatch(...)]` or in two on the same variant (closes #557).
- Declaring `#[dispatch(inputs = ...)]` (or `CommandConfig::input`) no longer spends the command's pre-dispatch registration, so a command can resolve an input chain and register a pre-dispatch hook through `AppBuilder::hooks` at the same time. The chain resolved through the same registration the application writes to, so `build()` refused the pair with a message naming a hook the command never declared (closes #556).
- **Breaking:** a command's input chains now resolve before every pre-dispatch hook, whichever order they were declared in. `.input(..)` used to register an ordinary pre-dispatch hook, so a hook written ahead of it ran first and could shape what the chain read. No pre-dispatch hook — from `CommandConfig` or from `AppBuilder::hooks` — can precede resolution now; an application that depended on one does that work in the chain's own source instead (closes #556).
- The collision a command still hits when it registers hooks for one phase from both `CommandConfig` and `AppBuilder::hooks` names what each side registered — `command_with("show", ..)` or the `#[derive(Dispatch)]` variant on one side, `AppBuilder::hooks("show", ..)` on the other — so both call sites are findable from the error alone (closes #556).
- A command declaring both `questionnaire::<T>()` and an input chain named `questionnaire` is now refused with the same message in either declaration order: `questionnaire` is reserved for command questionnaires. Declaring the chain second used to report a duplicate input name instead, because the chain then resolved after the questionnaire hook (closes #556).
