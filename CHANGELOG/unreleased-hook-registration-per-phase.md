- `#[dispatch(pre_dispatch(first, second))]` names several hooks for one phase and runs them in written order; `post_dispatch` and `post_output` take the same list. The single-path spelling, `pre_dispatch = path`, is unchanged. Repeating a phase key on one variant now fails expansion and names the key, whether the occurrences sit in one `#[dispatch(...)]` or in two on the same variant (closes #557).
- Declaring `#[dispatch(inputs = ...)]` (or `CommandConfig::input`) no longer spends the command's pre-dispatch registration, so a command can resolve an input chain and register a pre-dispatch hook through `AppBuilder::hooks` at the same time. Chain resolution runs before the handler and before every one of the command's own pre-dispatch hooks, whichever order they are declared in (closes #556).
- The collision a command hits when it registers hooks for one phase from both `CommandConfig` and `AppBuilder::hooks` now names what each side registered, so both call sites are findable from the error alone (closes #556).
- A command declaring both `questionnaire::<T>()` and an input chain named `questionnaire` is refused in either declaration order: `questionnaire` is reserved for command questionnaires (closes #556).
