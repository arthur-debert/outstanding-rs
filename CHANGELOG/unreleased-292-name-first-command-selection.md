- Select the command lexically, before parsing (issue #292, ADR-0018). The token in command position is read as a name: if it names a command, that command is what the line means; only a line that names none takes a default command. Under the old parse-first ordering a flat CLI with required root arguments could not have a working `help` word — the requirements fired before anything could decide what the word meant, so an injected `help` subcommand was advertised in help output and could never run. `help` is now installed for CLIs with subcommands and for flat CLIs with no positionals, and behind the new `.help_word(true)` for a flat CLI with positionals, where a bare word is data and only the application knows whether its domain excludes it (`--` is the escape). **Breaking:** `DefaultCommandContext::matches()` is removed — a decision taken before parsing cannot be handed parse results, which drops flag-conditional default selection; a flag that chooses a command should be a command. `standout-dispatch` no longer privileges the name `help` in `extract_command_path`, `get_deepest_matches`, or `has_subcommand`, so an application's own `help` command dispatches like any other.
