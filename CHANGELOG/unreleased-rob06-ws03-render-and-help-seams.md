- Size a whole table from a template (issue #359). `tabular()` and `table()` take a `rows=` argument — the row arrays you are about to render — and resolve every `{"min": n}` / `{"min": n, "max": m}` column against the widest cell those rows hold, which is the measurement a formatter that receives one row at a time cannot make for itself. `table()` measures its `header=` row alongside the data, so a header wider than its column is no longer truncated. Without `rows=` nothing changes: a bounded column still lands on its `min`, and leftover width still goes to the rightmost bounded column when the table has no `"fill"`. A column carrying `sub_columns` is not measured from `rows=` — its sub-columns are resolved per row against the parent's width. See [Introduction to Tabular](docs/crates/render/guides/intro-to-tabular.md), Step 4.
- List `-h`/`--help` and `-V`/`--version` on themed help pages (issue #334). The help extractor reads the `clap::Command` *after* `build()`, which is when clap creates its own arguments; before, it read the declared command and no page could tell a reader those flags existed. Every themed help page gains a `-h, --help` row, and an application that sets a version gains `-V, --version`, both after the application's own options — a rendered-byte change for any downstream pinning a help page. Two consequences of reading the built command are handled in the same pass: a valueless flag (`SetTrue`, `Count`) no longer states the `false`/`0` default clap materialises and hides from its own page, and clap's generated `help` subcommand is identified by provenance — it is absent from the declared command — rather than by the spelling `help`, so an application's own `help` subcommand keeps its COMMANDS row. In `standout_test::clap_parity`, the `DELIBERATE_OMISSIONS` entry exempting clap-generated subjects is gone; `Omission::ClapGeneratedSubcommands` replaces it, covering the generated help word alone and no argument.
