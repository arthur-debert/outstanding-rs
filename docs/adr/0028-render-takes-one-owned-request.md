# Render takes one owned RenderRequest

`RenderRequest` is an owned type: it has no lifetime. The pure function is `render_request(request: &RenderRequest) -> …` — it takes that owned type by reference. Existing `render(template, data, theme)` and siblings stay as detect-then-call wrappers that build a request and delegate to `render_request`. Rust has no free-function overloading, so the pure entry cannot keep the name `render` while those wrappers remain. `RenderRequest` carries everything the pure function needs: data, a render-time `TemplateRef` (`Named`, `Inline`, or `Absent`), theme, format, `TargetProperties`, the engine (`Rc`), an optional template registry, an optional context registry, and an optional CSV projection. A `ContextRegistry` or named `TemplateRef` on the request is an explicit external dependency (provider callbacks; ADR-0019 rereads file-backed templates); the leaf does not read framework-owned detectors or process globals. `Presentation` is deleted; the artifact path that today stores a `Presentation` until after the write stores a `RenderRequest` instead.

A second argument (`render_request(request, engine)`) was rejected: standalone and framework would grow two call shapes, and the artifact path would still need a side bundle — `Presentation` under another name. Keeping `Presentation` as a private adapter was rejected for the same reason. `command_path` stays off the request; it is glue error context, not a render input. Passing the request by value was rejected as unnecessary: ownership is a property of the type (so the artifact path can store it), not of the call.

Render-time `TemplateRef` moves to `standout-render` so the leaf can interpret named, inline, and absent templates. `Convention` stays glue-private: `build()` materializes it to `Named`, and the leaf never sees it. Help and topics join this pipeline as ordinary renders. Framework defaults and build-time app overrides are named registry templates: `build()` registers them, and ADR-0020's tag check applies. Public `HelpConfig::template`, `TopicRenderConfig::topic_template`, and `list_template`, and standalone `render_help` / `render_topic` (no `build()`), stay: those strings become `TemplateRef::Inline` with equivalent tag validation at request construction. The fields are not deleted. Named-registry-only help was rejected because it would break that public standalone API.
