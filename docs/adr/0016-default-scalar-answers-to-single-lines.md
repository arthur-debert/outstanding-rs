# Default scalar answers to single lines

A scalar answer is a single line by default; free prose is the marked exception (`ScalarKind::Text`, declared in derived questionnaires with `#[question(prose)]`). The distinction is not an input-mechanics concern — in the sheet format any field can physically hold multiple lines, and interactive entry is line-based either way — and it is kept for two structural reasons. First, single-line fields are the format's cheapest damage detectors: an answer sheet's structure hangs on tag lines, and a deleted or mangled tag silently merges the orphaned text into the preceding field's answer; a single-line field then fails loudly at decode, where a prose field would accept the merge and let a wrong value flow downstream — the silent variant of exactly this failure was demonstrated in the WIZ02 deep review. Second, most CLI answers are identifiers, paths, or choice values, where an embedded newline is always an error; rejecting it in the kind system spares every application validator from checking `\n` by hand.

The framing follows the observed ratio (the bootstrap wizard has one prose field in ten): single-line is the default contract of a scalar answer and needs no marking, while prose opts out per field. The consequences accepted: prose fields forgo the merge-detection tripwire (mitigated by the sheet parser's `<id:` answer-content warning), and a questionnaire consisting mostly of prose fields carries fewer structural checks — a shape the model tolerates but does not optimize for. Kind is semantic and fingerprinted, so flipping a field between single-line and prose invalidates previously rendered sheets, as a change to accepted answers should.
