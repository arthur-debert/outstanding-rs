# Select the command lexically, before parsing

Command selection reads the first non-program token as a name: if it names a command, that command is dispatched; only when no name matches is the default command inserted and the line parsed. This replaces an ordering in which resolution ran only after an initially successful parse. The parse-first ordering was adopted to keep Clap authoritative, but it cannot express a flat application that offers `help` — such an application is not single-command at all, but two commands one of which is default, and under parse-first the root's required arguments fire before standout is ever asked what the word meant, so an injected `help` subcommand is advertised in help output and can never run. Reading the name first makes selection a total function of one token: local, order-independent, and unaffected by whether the rest of the line parses. The tempting alternative — parse as the default command and fall back to the command table when that fails — is rejected because it is failure-driven: a word's meaning would depend on unrelated tokens elsewhere on the line, the failing parse holding the useful diagnostic would be discarded in favour of the second parse's, and making an argument optional would silently flip a word's meaning across a release with no change at the call site.

The consequences accepted follow from the same honesty. A decision taken before parsing cannot be handed parse results, so `DefaultCommandContext` no longer exposes the root matches; application state, the stdin terminal fact, and the environment remain, none of which pass through Clap. This removes flag-conditional default selection — a global flag whose presence chooses which command a naked invocation means — a pattern that already required the flag to be declared on the root and consumed by the target command, and that reintroduced precisely the non-locality this ordering exists to remove; an application that wants a flag to select a command should make it a command. Clap stays authoritative for everything after selection, so invalid syntax remains its usage error, produced by the single authoritative parse rather than guessed at from a rejected one. Reserving a bare word out of the data namespace stays a per-application choice, because only the application knows whether its positional domain can contain that word: standout installs `help` for commands that have subcommands and for flat commands with no positionals, and otherwise only behind an explicit opt-in, leaving `--` as the escape for an application that reserves it and later needs the literal string.
