# Detect TargetProperties at the crate edge

`TargetProperties::detect() -> TargetProperties` is the one function that asks the process what the destination looks like. It lives on the type, in `standout-render`, because that crate already owns width, color, color-scheme, and icon probing. It fills width, stdout and stderr terminal-ness, stdout and stderr color capability, color-scheme, and icon mode — those detected facts have no App fallback. Convenience wrappers (`render`, `render_with_output`, …) call it at their edge, put the result on a `RenderRequest`, and call `render_request`. `App::run` calls it once per invocation and overwrites ambiguous-width with the application's configured policy. Template functions, tabular, width, and the rest of the leaf never call it. Tests never call it either: they construct `TargetProperties` directly.

A detect-only-inside-`App::run` path was rejected: standalone convenience wrappers have to detect too, and duplicating the probes in glue is the copy this work exists to delete. Keeping the current `detect_terminal_width` / `detect_color_capability` / `detect_color_mode` / `detect_icon_mode` cluster plus `set_*_detector` overrides was rejected: those functions *are* the ambient API the Spec removes. A separate detect module was rejected as a third place to look for one function.

Ambiguous-width is not probed. Standout does not guess it from locale; `detect()` defaults it to `Narrow` (the compatibility default) and `App::run` then applies the app's policy. It is App-owned build-time configuration, alongside merged theme, output-mode fallback, and template registry — not a detected terminal fact. The old detector and setter functions go away.
