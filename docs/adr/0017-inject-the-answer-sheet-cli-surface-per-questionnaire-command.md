# Inject the answer-sheet CLI surface per questionnaire command

A command declared with a questionnaire input (`#[dispatch(questionnaire = …)]` on the variant, or the equivalent builder call) receives its complete answer-sheet CLI surface from the framework: the builder augments that command's clap definition with `--answers FILE` (with `-` for piped stdin), `--yes`, and a `questions` subcommand, while answer resolution rides the existing `InputChain`/`InputCollector` seam (a questionnaire source resolving sheet-or-interactive pre-dispatch, so the handler simply receives the typed struct) and `--yes` feeds the framework-owned attended confirmation gate. The alternative — shipping only the resolution machinery and having each application declare the flags in its own clap enum, as the bootstrap wizard originally did — was rejected because it forfeits the point of the declaration: every app would restate the same three declarations per questionnaire command, and their spellings, precedence, and confirmation posture could drift between apps, whereas injection makes the surface uniform across every standout application.

Per-command argument augmentation is a new builder capability, but not a new policy: it extends to individual commands what the builder already does globally for the reserved `--output`/`--output-file-path` flags (inserted into all commands, with explicit opt-out knobs), and it follows the sibling precedent of clapfig's batteries-included `config` subcommand tree that a host application mounts wholesale. The consequences accepted: `--answers`, `--yes`, and `questions` become framework-reserved names on questionnaire commands (collisions with app-declared args are a build-time error, matching the reserved-globals policy); the injected surface is versioned with the framework rather than per-app; and the confirmation invariants established in WIZ02 — submitting a sheet never implies consent, no stdin byte or EOF can confirm, an absent attended terminal is an error, the test seam is debug-only — move into the framework unchanged and apply identically to every questionnaire command.
