# Check glue invariants with tests

The four glue invariants — `standout` depends on none of `serde_yaml` / `csv` / `quick-xml`; `MiniJinjaEngine::new()` exists only in `build()`; glue does not invent a theme / mode / width default; a new output mode touches the enum and the serializer registry — are checked by tests in the `standout` crate, run by `pixi run test`. A Cargo.toml parse fails the first; a source scan of `crates/standout/src` fails the second and any glue `match` on `OutputMode` that serializes (the copies that would make a new mode a nine-file edit). Point-of-use defaults are not a grep: they die because glue builds the request from `App`'s build-time fallbacks plus this invocation's flags and detection, and the ROB01 snapshot matrix is what fails if a call site invents another.

`cargo deny` was rejected: it can see crate dependencies and nothing else, so (2) and (4) would still need tests and we would maintain two tripwires for one policy. A compile-fail crate and a custom clippy lint were rejected as extra packages or toolchains that still implement a grep.
