# Adopt prose answer sheets with stable identities

Questionnaire answers use a dedicated prose-first document rather than a general configuration format: a line-terminal `<id:...>` tag identifies each question — a line is a question line if and only if the tag is its last non-whitespace content, and the answer is all text between a question line and the next — while visible numbering, wording, and type hints remain cosmetic. A group occurrence is a line ending with the group's tag, so repeated items are counted by counting tag lines, exactly as copy-the-block editing implies. There is deliberately no escaping mechanism: an answer line that itself ends with a schema-valid tag is misparsed as a question line, an accepted trade-off guarded by a warning-level diagnostic whenever accepted answer text contains `<id:` anywhere. `standout-input` publicly owns rendering, parsing, normalization, and diagnostics, while applications own questionnaire definitions, domain conversion, flow, and side effects; this keeps the format reusable without exposing application models such as the bootstrap wizard's `ProjectSpec`.

Each document carries an answer-format version, questionnaire ID, and fingerprint of the canonical semantic definition. Version 1 accepts only exact identity and fingerprint matches, infers repeated items from stable group-tag occurrences rather than display numbers, and rejects incompatible sheets instead of fuzzy-matching or migrating them; this deliberately trades automatic reuse of stale documents for predictable interpretation and leaves a future migration protocol to evidence from real schema evolution.

> **Amended by ROB06/WS02 (#351):** everything above describes the sheet the framework renders, which is now one `AnswerSheetFormat` — `StandoutAnswerSheet`, the default a questionnaire command reads. An application whose own spec pins the shape of the file supplies another format, from scratch or over the tagged body alone (`Questionnaire::parse_answer_sheet_body`, the parse without the preamble). A format decides how bytes become `RawAnswers` and nothing else: the definition, the fingerprint, decoding, whole-form rules, review and confirmation are unchanged.
