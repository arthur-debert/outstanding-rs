# Carry a template as a typed reference resolved at render

A command's template is a `TemplateRef` — a named registry entry, inline source, or a declared absence — and a named reference survives to render rather than being collapsed into content earlier. `build()` resolves each name only to validate it exists, reporting the reference and its near matches when it does not. What this replaces is a `String` that was one of three unrelated things — registry content, a filesystem path, or empty — disambiguated at render by asking the engine whether it happened to know the name. That guess produced four silent failures from one decision: a missing template rendered nothing and exited zero, a typo'd name was rendered *as* MiniJinja source, `.templates()` called after `.commands()` yielded an empty template because resolution ran at registration, and `.template_dir()` handed the engine a file path to render as a template body. Ordering independence is a consequence rather than a separate fix: registration records a name, `build()` resolves, so the documented call orders stop disagreeing. `.template_dir()` is removed rather than repaired — `.templates_dir()` already loads directories into the registry and registry file entries already reread on demand, so the capability it named exists without it.

The reference must be resolved through the retained `TemplateRegistry` at render, not through a copy the engine compiled earlier, and this is the part an implementation can get wrong while appearing to follow the decision. `TemplateRegistry::get_content` is what rereads a file-backed entry; `TemplateEngine::render_named` renders whatever source was compiled into the engine. Today `build()` walks the registry and copies every template into the engine — discarding the compile result, so a template that fails to parse is silently skipped — which means an engine-cached `render_named` serves a build-time snapshot. Keeping the name alive to render therefore buys nothing on its own: hot reload, which documentation defines as debug file-backed resources being reread on render and which `embed_templates!` stores absolute source paths to serve, survives only if render goes back through the registry, refreshes changed file-backed content, and recompiles before rendering, including named templates reached through `{% include %}`. A file that has disappeared or no longer parses is a render error naming the template and its path; it is not a silent fallback to a stale copy, and it is not a discarded result.

Absence is typed, carrying why: `Silent`, `StructuredOnly`, or `Binary`. The reasons are not decoration, because they diverge at render when a handler returns renderable data. For `Silent` and `Binary` that is a contract violation and an error naming the command. For `StructuredOnly` the mapping is total and stated here so every entry point implements the same one, keyed on the mode as *requested* rather than on what terminal detection would resolve it to: `auto` serializes as JSON; an explicitly requested `json`, `yaml`, `xml`, or `csv` uses that serializer; and an explicitly requested `term`, `text`, or `term-debug` is an error naming the command as structured-only, because those modes select a presentation the command does not have. Requesting `auto` explicitly and passing no `--output` at all are deliberately the same case — `auto` means the framework chooses, and for a command whose output is data the framework chooses JSON — so nothing needs to distinguish them and `OutputMode::Auto` continuing to represent both is correct rather than a latent ambiguity. Keying on the requested mode is what makes a bare invocation in a terminal yield JSON instead of the presentation-mode error. This is the shape `cargo metadata` has, emitting JSON with no flag asked for. Untyped absence was considered first and rejected once the three cases proved to behave differently; letting a `StructuredOnly` command pin one format and ignore `--output` entirely was rejected separately, because a global flag that silently does nothing on some commands is the class of surprise this work exists to remove — hence the error rather than silence on the presentation modes. Declaring absence is mandatory: a command that names neither a template nor a reason fails `build()`. That is the line the whole change draws — quiet output is legitimate when it was declared, never when it was defaulted into.
