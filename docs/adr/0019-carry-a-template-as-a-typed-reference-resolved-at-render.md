# Carry a template as a typed reference resolved at render

A command's template is a `TemplateRef` — a named registry entry, inline source, or a declared absence — and a named reference survives to render, where the engine looks it up. `build()` resolves each name only to validate it exists, reporting the reference and its near matches when it does not. The rejected alternative was collapsing names to content during `build()`, which reads simpler at the render site but freezes templates at build time: registry entries backed by files are deliberately re-read on each render, which is the whole of the hot-reload promise, and `embed_templates!` stores absolute source paths for exactly that reason. What this replaces is a `String` that was one of three unrelated things — registry content, a filesystem path, or empty — disambiguated at render by asking the engine whether it happened to know the name. That guess produced four silent failures from one decision: a missing template rendered nothing and exited zero, a typo'd name was rendered *as* MiniJinja source, `.templates()` called after `.commands()` yielded an empty template because resolution ran at registration, and `.template_dir()` handed the engine a file path to render as a template body. Ordering independence is a consequence rather than a separate fix: registration records a name, `build()` resolves, so the documented call orders stop disagreeing. `.template_dir()` is removed rather than repaired — `.templates_dir()` already loads directories into the registry and registry file entries already re-read on demand, so the capability it named exists without it.

Absence is typed, carrying why: `Silent`, `StructuredOnly`, or `Binary`. The reasons are not decoration, because they diverge at render when a handler returns renderable data. For `Silent` and `Binary` that is a contract violation and an error naming the command; for `StructuredOnly` the framework serializes the data in human modes as it already does in structured ones, because such a command's output *is* data — the shape `cargo metadata` has, emitting JSON with no flag asked for. Untyped absence was considered first and rejected once it became clear the three cases behave differently; the alternative of letting a `StructuredOnly` command pin its own format and ignore `--output` was rejected separately, because a global flag that silently does nothing on some commands is the class of surprise this work exists to remove. Declaring absence is mandatory: a command that names neither a template nor a reason fails `build()`. That is the line the whole change draws — quiet output is legitimate when it was declared, never when it was defaulted into.
