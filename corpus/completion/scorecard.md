# The completion six — first blind runs against 9.0.0

The six completion archetypes, each run blind once against standout **9.0.0**.
These are first runs: no archetype here has an earlier row, so every row's
`Comparable` column reads `single run` and nothing below is a delta. What this
records is one data point per archetype and the findings the six runs produced.

The objective figures are generated from the committed reports; the readings
under them are authored, and each says which of the two it is.

## What was run, and against what

Each run pins standout **9.0.0** from crates.io and provisions the published
documentation snapshot taken at the **v9.0.0 tag** (`docs_commit` 1642d4e), so
the agent's documentation and its dependency describe the same release. The
same agent answered all six (Claude Code 2.1.252, `claude-opus-5[1m]`), and
every report states `framework_source_excluded: true`. The committed evidence
for each run is the sanitized `report.json` and `transcript.jsonl` under
`runs/<run-id>/`, by the rules `../README.md` states for any committed run.

## What the first runs say

**Two suites assert a help line standout does not write.** `dockerlike`'s two
failures — its only ones, out of 46 cases — require a single stdout line
containing both `Usage` and the command path. Standout's help page writes the
header and the invocation on separate lines by design, so no casing correction
repairs these two. Same class as `ghlike`'s, recorded as a second archetype on
[#460](https://github.com/arthur-debert/standout/issues/460).

**Two invariant checks ask a question the archetype cannot answer spec-first.**
`cargolike`'s 2 invariant failures are the cross-mode equality check on
`config list`, a command whose content *is* the resolved output mode
([#465](https://github.com/arthur-debert/standout/issues/465)). `kubelike`'s 8
are `stdout parses as JSON` on four commands the archetype declared `rendered`
before an implementation existed; the produced application answered its `-o`
vocabulary with artifact bytes, which reach stdout unchanged
([#467](https://github.com/arthur-debert/standout/issues/467)). Both sets are
the whole of their run's invariant failures, and both archetypes' acceptance
suites pass every case they were expected to.

**The config-layering gap cases passed, and that is not the framework closing
them.** `cargolike` declared 22 cases `expected = "fail"` against the PAR01
config-layering gap and 21 passed; `gcloudlike` declared 24 and all 24 passed.
A gap case that asserts only what the CLI does cannot detect a missing
framework facility, because the application can supply it — and both did, at a
cost that shows up in their workarounds answers (`cargolike` builds and parses
the command line twice to resolve configuration before `App::build()`;
`gcloudlike` rewrites argv before `app.run`) rather than in an outcome column.

**One predicted gap held.** `brewlike`'s 2 `expected-fail` cases are its
versioned-machine-contract group: a schema version stamped on the payload and
help as a versioned machine document. Nothing in 9.0.0 offers it, and the
archetype's spec says so up front.

**Documentation errata.** Every documentation claim these runs caught being
wrong, contradictory, or missing-but-load-bearing is collected in
[#464](https://github.com/arthur-debert/standout/issues/464), re-checked
against `main` before filing.

**Five of six exit sheets are uncollected.** The reports carry the answers that
parsed and report `collected: false`, on the same scalar `confidence` field
that cost the re-run its sheets
([#462](https://github.com/arthur-debert/standout/issues/462)). The prose above
reads the committed answers, not a collected sheet.

## What this measures, and what it does not

One run per archetype, one agent, one release. There is no repetition here, so
no figure separates the framework from the run that produced it, and no
acceptance ratio is comparable with another archetype's — the suites differ in
size and in how much of each was specced past current capability on purpose.
What these six rows are is the baseline the next run of each archetype is read
against.
